# Grok Bot · 冷咖啡记忆管理

工作台版本：`3.2.0-preview.8`。入口在「一键破甲」的 **Grok Bot 模型卡片 → 管理 Bot 云端记忆**。仍是十五个 AI 模型席位，原来的本地安装、备份、卸载和完整技能扩展继续保留。

## 使用

1. 在 Windows 或 macOS 安装并登录 Grok Bot 桌面客户端，至少创建一个 Bot。
2. 打开冷咖啡工作台，在 Grok Bot 卡片进入记忆管理，点「连接 / 重新检测」。打开面板本身仅显示界面，点击连接才读取 Grok Bot 专用登录记录并请求 Bot 列表。
3. 选择 Bot，点「重新读取 / 验证」。界面标明来自服务端列表还是 Bot 对话导出。可按原文搜索，或主动导出当前列表为 JSON；导出包含你保存的记忆正文，请自行保管。
4. 输入要保存的原文，选择「账号共用 / 仅此 Bot」和「普通事实 / 指令偏好」，点「预览写入」。确认 Bot、范围和完整正文后勾选确认，再发送。
5. 需要冷咖啡原欢迎词时点「填入冷咖啡原欢迎词」。正文完整保留四个 QQ 群和 Telegram 群、频道；仅填入不发送。使用原文预设时保留原文件换行，用户编辑后按输入框内容提交。
6. Bot 回复后，点「重新读取 / 验证」核对原文、范围和属性。随后到 Grok Bot 新开对话，单独发送 `冷咖啡`，实际检查欢迎词和工作流表现。
7. 忘掉某条记忆：在已读取原文下点「预览忘掉」，确认后发送，再重新读取核对。忘掉按原文请求 Bot 处理；同一正文存在多个范围时，需要额外核对实际处理结果。

「停止等待」仅结束本机等待，不撤回已发往服务端的操作。关闭面板或断开会清空本机连接、Bot 列表、预览和读取缓存；云端已保存内容保持原状态。

## 结果怎么看

| 界面证据 | 代表什么 | 尚待核对 |
| --- | --- | --- |
| Bot 已回复确认 | 本次 nonce 之后收到精确 request ID 对应的 `ok:true` | 是否实际保存 |
| 原文、范围与属性匹配 | 后续单独读取找到完全一致的原文、scope、tier | 是否在新会话实际采用 |
| 找到原文，范围或属性待确认 | 读取里找到正文，但元数据不一致或未知 | 范围、类型与平台行为 |
| 本次读取未见原文 | 此次导出没有返回该条正文 | 对话导出可能遗漏；删除或持久化结果还需目标客户端核对 |
| 尚未验证 · 新会话 | 本工具没有创建并检查目标 Bot 的新会话 | 用户在目标软件新开对话实际测试 |

个人 Bot 的直接列表接口可能受团队权限限制，此时通过 Bot 的记忆能力只读导出。对话导出仍属于模型返回的结果；`more:true` 会显示可能未列全。网络错误、登录失效、限流等状态不当成空列表处理，也不无条件转为对话成功。

## 连接与资料边界

- 只读取 Grok Bot 固定目录的 `sand-secrets.json`、所需系统加密状态与客户端版本。不读取浏览器登录、其他软件凭据或账户邮箱/昵称。
- Windows 使用当前系统用户的 DPAPI 和 AES-GCM；macOS 使用 `Grok Bot Safe Storage` 钥匙串项与 AES-CBC。系统钥匙串可能要求使用者确认。
- 凭据只留在主进程内存，界面只收到连接检查结果、Bot 列表与记忆正文。断开释放引用；临时解密 Buffer 尽量清零。JavaScript 运行时不保证已分配字符串的即时物理清除。
- 固定服务目标为 `https://api2.cursor.sh/aiserver.v1.GrokBotService/`，仅四个已列明 RPC 方法。禁止凭据随重定向发送；主进程处理超时、取消、响应大小和错误脱敏。网络沿用现有系统设置。
- 默认没有本地记忆数据库、自动导出或操作日志；用户主动导出的记忆 JSON 不含连接令牌和机器标识。
- Linux 的其他工作台功能继续使用；此版本的 Grok Bot 本机登录连接仅实现 Windows / macOS。
