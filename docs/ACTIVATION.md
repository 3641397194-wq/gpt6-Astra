# 冷咖啡启动说明

## 给使用者

**启动口令：冷咖啡。完成安装与接入后，在目标软件的对话框里单独发送这三个字。**

- 只安装文件或打开安装器，不代表会话已激活。
- 严格控制层只接受整条消息去掉首尾空白后恰好为 `冷咖啡`。
- `cold coffee`、`冷咖啡启动`、包含口令的长句均不触发严格开关。
- 原稿欢迎页、三个 QQ 群号和原词包保持不变。
- 新建会话、切换席位或重置开关后需重新输入。适配层当前采用内存状态，闲置 30 分钟过期，重启服务后清空。

## 两种模式，务必区分

### 原版兼容部署

保留原词包，写入其原有目标文件，并增加差异预览、事务备份、哈希检查及版本恢复。原稿存在英文别名和默认执行描述，**原版兼容部署不是严格待机开关**。欢迎页是原词包中的文案，不是底层模型权限证明。

### 严格消息控制层

`desktop/src/lib/activation-gate.js` 是真实程序开关。客户端必须在消息进入模型前调用它，并保证待机期间不从其他全局指令文件加载原词包。否则仅在提示词里写“待机”，并不构成可靠控制。

当前工作台提供该程序开关的本地交互验证，尚未替所有第三方客户端完成接入，也未连接真实模型服务。

接入方应当：
1. 为每个用户会话创建独立 gate 会话，不跨用户共用 ID。
2. 每条消息先经过 gate；`active: false` 时不附加原词包。
3. `activatedNow: true` 时展示返回的原欢迎页。
4. 已激活会话使用返回的 `instructionText`，按目标客户端支持的配置接口提交；不得把本文档当作任意客户端已支持该接口的证明。
5. 客户端的新会话、退出、重置动作同步清理 gate 会话。

## 真实验证与效果

文件写入、文件一致、客户端加载与模型响应是四件不同的事。工作台检查文件完整性；模型实际响应需要在接入的客户端另行验证。没有预设或伪造突破成功率。
