# 冷咖啡安卓版

冷咖啡手机端用于在安卓手机上接入模型 API、流式聊天并整理会话；默认推荐冷咖啡中转，也允许添加其他兼容服务商。3.3.0-preview.3 将 **GPT-6.2 Astra** 与 **GPT-6.2 Sol** 作为模型选择焦点：先读取当前 Key 的 `/v1/models`，实际请求使用响应中的完整模型 `id`。展示名称不代表账号已开通。移动工作台继续保留，电脑端负责本机工具、文件处理与长时间任务管理。

## 安装

1. 确认发布页的 **Assets** 和校验文件已上线，再下载 `ColdCoffee-Mobile-Android-3.3.0-preview.3.apk`。
2. 用安卓手机打开 APK。系统若询问是否允许该下载来源安装应用，按系统提示为这次安装授权。
3. 打开“冷咖啡”。安装包不包含作者或其他顾客的 API Key，需要填写你自己的 Key。

最低系统为 Android 8.0。首版是预览构建，建议先确认设备运行与中转兼容性，再迁入重要会话。已有安装版本如因签名不同而升级失败，先保存需要保留的资料，核对发布说明和安装包来源；不要直接覆盖签名不一致的应用。

## 接入冷咖啡中转

1. 打开应用中的冷咖啡接入入口，接口地址预设为 `https://coldcoffeeai.com/v1`。
2. 在 [coldcoffeeai.com](https://coldcoffeeai.com/) 开通付费服务，取得自己的 API Key。
3. 将 Key 填入接入表单，保存后读取模型列表。
4. 选择 `/v1/models` 返回的准确模型 ID，回到聊天页发送消息。GPT-6.2 Astra / Sol 仅在当前服务商返回对应项时可选。

接好模型后也可以打开底部的“工作台”，选择 REA 逆向分析、红队渗透、API 审计、游戏客户端研究、样本与取证或证据报告。填写 `TARGET`、`HOST`、接口、日志、样本说明和输出要求，任务会通过当前服务商流式返回；支持停止、复制、分享和本机记录。大体积二进制、设备连接和实际工具链仍交给电脑端处理。

中转站的模型、价格、额度和工作流能力，以中转站实际提供为准。软件不会因为显示某个模型名称而自动赋予该模型的使用权限。模型请求由顾客的手机发送到顾客选择的服务商。

## 接入其他中转

在服务商管理中添加服务商名称、API 基址和自己的 Key，再读取模型。接口地址通常填写服务商提供的 `/v1` 基址；如果模型列表接口不可用，可按服务商说明填写准确的模型 ID。

当前连接面向 OpenAI 兼容接口，聊天协议依应用中的选项配置。`/chat/completions` 和 `/responses` 是否可用取决于所选服务商。不要把 Anthropic、Gemini 的原生接口地址直接当成 OpenAI 兼容接口使用；先确认服务商提供的兼容入口。

HTTPS 中转通过安卓原生网络层连接，使用系统 TLS 证书校验。应用不会为了连接失败而关闭证书验证。网络故障、鉴权失败、余额不足、模型不存在和接口不兼容，需要分别按实际错误检查。

## 日常使用

- **选择模型：**先选择服务商，再选择该服务商的模型。不同服务商可以配置不同的 Key。
- **流式聊天：**回答到来时逐步显示；需要结束本次生成时点击停止。
- **会话记录：**在本机保留会话，切换历史后继续对话。删除前确认需要保存的内容。
- **Markdown：**支持常见段落、列表和代码显示；模型输出按不可信内容处理。
- **移动工作台：**提交结构化研究任务，查看流式结果；文本日志或配置片段可作为附件发送。
- **社区与服务：**打开社区页查看 QQ 群二维码、Telegram 群与频道，以及冷咖啡中转和收费服务入口。
- **隐私与许可：**在关于页查看许可证、第三方来源和源码入口。

手机端不等同于电脑工作台的十五个本地安装席位。手机负责模型对话、移动研究任务提交和结果整理；电脑端已有安装、备份恢复、路由、Harness、本机文件和工具执行功能继续按电脑端文档使用。

## 费用与收费服务

手机客户端公开源码；使用模型 API 会按照所选服务商的规则产生费用。

冷咖啡提供三类服务：

| 服务 | 说明 |
|---|---|
| 付费 API 中转 | 在 [冷咖啡官网](https://coldcoffeeai.com/) 开通自己的 Key，手机和电脑均可接入。 |
| 收费闭源本机工作流 | 独立交付到顾客电脑，可使用顾客已有订阅或其他中转。 |
| 收费定制闭源工作流 | 进群与管理私聊，沟通需求、方案、价格与交付范围。 |

独立闭源交付不包含将本移动端的 GPL 衍生代码转为闭源。

## 从源码构建

对应源码在同一发布页提供：`ColdCoffee-Mobile-Source-3.3.0-preview.3.zip`。也可从仓库的 `v3.3.0-preview.3` 标签获取 `mobile/` 目录；发布前请先核对资产与标签确已生成。

先安装 Node.js、JDK 17 和 Android SDK，并按原生工程要求准备 SDK 35。具体版本以 `mobile/package-lock.json`、`mobile/android/` 的 Gradle 配置和 wrapper 为准。

完整仓库克隆后进入 `mobile`；独立源码 ZIP 解压后进入 `coldcoffee-mobile`。从含 `package.json` 的移动端目录开始执行：

```sh
npm ci
npm test
npm run build
cd android
./gradlew assembleDebug
```

Windows 最后一行使用：

```powershell
.\gradlew.bat assembleDebug
```

构建发布版本时使用 `assembleRelease`。发布签名材料由构建环境单独提供；自行构建的 debug 包与公开发布包可能采用不同签名，不能直接混装覆盖。不要将密钥库、签名密码、顾客 Key 或本地 Android SDK 路径提交到源码仓库。
