# 冷咖啡可视化融合预览

这版把原有工作台、Magpie 本机网关和冷咖啡原创可视化界面放进同一个桌面应用。原有十五个模型席位、欢迎词、技能包、DeepSeek 皮肤、Grok Bot 记忆管理及社群入口继续保留。

## 开始使用

1. 打开软件，进入「可视化工作台」。
2. 想先看效果，点「体验可视化」。请求实际经过随包网关，使用本机演示服务，零费用。
3. 正式接入时点「一键接入」，选择 Codex、Claude Code 或 DeepSeek Harness。
4. 填入顾客自己的冷咖啡 API Key，读取实际可用模型；也可添加其他中转。
5. 选择模型，检查原生配置变更，再点「备份并一键接入」。可选一并安装已有技能包。
6. 重新打开目标软件，新建会话，单独发送「冷咖啡」。真实请求经过网关后，连接图与上下文图会更新。

配置已写入、技能已安装、请求已经过网关和目标模型实际执行工作流，是分别验证的状态。启用提示词的效果仍需按模型实际测试。

## 可视化

本机第六版视觉预览使用原创成年白发女生、纸白文字、墨黑底色与少量猩红强调。主视觉、窗口头像、开屏、安装页、Grok 管理入口及各平台软件图标统一；主视觉与头像由 img2.6 高画质生成，图片来源参数与哈希记录在 `desktop/assets/brand-v6/provenance.json`。发行包仅包含完成的静态美术资源，图片服务的凭据及个人配置均留在本机。

首页上方为接入入口与主视觉，下方依次显示全宽多分支实时路由和上下文窗口，为模型分支、嵌套组与内容明细留出空间。三步接入、中转服务与社群入口位于图表下方。图表、数据、按钮均为真实交互组件，插画只负责视觉呈现。

正文和主要按钮采用 15～16 像素，说明文字至少 13 像素。显示跟随系统 DPI；窗口变窄或界面放大时按可用宽度重新排列卡片。

右上角「− / 百分比 / ＋」调整界面大小，支持 80%～200%，并记住上次的设置。点击百分比恢复 100%。也可使用 `Ctrl + ＋`、`Ctrl + −`、`Ctrl + 0` 和 `Ctrl + 滚轮`。窗口最大化、还原与最小化单独控制，保留已选界面比例。

- 路由图根据该请求的 `order`、`left`、`tries`、`group`、嵌套成员路径绘制，显示请求来源、本机网关、供应商/模型分支与连接状态，支持折叠。账号和 Key 使用匿名连接席位，不传递原始账号或密钥指纹。
- 候选顺序、休息/排除状态、每次尝试的 HTTP 状态与耗时、实际命中及切换过程来自网关记录。候选分支不代表实际调用，界面不重新推算路由原因。
- 可选择最近 100 条请求查看详情。接入模型的选择与正在查看的历史请求分别维护；其他请求的进行中状态不覆盖当前请求的完成状态。
- 请求、改道、客户端收到错误三项累计数来自引擎 `totals`；顶部的最近请求成功率与平均耗时只统计当前保留样本，两者范围不同。
- 主界面「管理路由组」读取引擎实际目录，可新建/编辑名称、成员顺序、基础策略和会话保持，支持组内嵌套其他组，并把路由组作为原生客户端的模型入口。保存配置与发起模型请求分开。
- 基础编辑保留已有条件规则、匹配模式、权重、单 Key 限定等高级配置；版本摘要检查防止覆盖其他窗口的新修改。规则编辑、权重细调、手动成员指定和单 Key 管理仍在完整引擎控制台，本版未把这些编辑器全部重新实现。
- 上下文矩形图显示系统提示、工具说明、技能、工作说明、文件、工具结果和会话内容，并按各类项目绘制工具名称、次数与词元用量。有已知窗口时，「总窗口」包含斜纹剩余空间；「放大已用内容」便于观察较小项目。
- 内容明细支持分类筛选和逐项原文读取；默认遮住正文，只有显式点击后读取。缓存命中率只使用当前回答尝试的供应商用量，不把先前失败尝试的缓存合计进去；未提供缓存计数时显示未知。
- 供应商返回用量时采用其总量，并按内容测量缩放各分区；供应商未返回时标明估算。未知的模型窗口上限保持未知。
- 最近请求可筛选真实中转、本机演示和异常请求；演示记录始终有独立标识。
- 原有工具箱和任务编排在连接后共用本机网关，无需重复填写供应商 Key。

只观测经过这个本机网关的流量。软件退出后网关随之停止；已接入客户端需要重新打开工作台才可继续使用该网关。

## 完整核心与原创部分

随包保留 Magpie 固定版本核心，没有删裁其编译能力。这与“所有上游功能均已在冷咖啡主界面重新实现”是两件事。本版主界面接入了路由拓扑、实际尝试时间线、基础路由组管理与上下文明细；高级供应商设置、规则编辑、插件、资源库等继续由「完整引擎 / 高级功能」在同一桌面应用内打开。首页与接入流程由冷咖啡重新实现。

引擎在独立的配置与客户端暂存目录运行，默认关闭订阅账号自动发现、遥测与自行更新。控制台的客户端目录是暂存目录；实际接入通过冷咖啡主界面的检查、备份、写入和恢复流程完成。

目前主界面自动接入入口覆盖 Codex、Claude Code 和 DeepSeek Harness，调用上游完整原生配置适配器生成结果。其他支持自定义 API 地址的客户端可使用「本机连接信息」手动接入；原有十五个技能安装席位与网关自动配置入口分别维护。

原创部分：冷咖啡的页面布局、连接图、矩形图交互、新手引导、凭据桥接、事务式接入、原技能包联动和社群服务界面。Magpie 核心及第三方组件保留其作者与许可归属。

## 配置与凭据

- 顾客的供应商 Key 由 Electron 主进程持有。选择记住时使用系统加密存储；系统仅提供明文后端时保持本次运行使用。
- Magpie 的供应商配置只记录随机的本机桥接凭据，真实供应商 Key 由本机桥接在转发时加入。
- 控制接口绑定回环地址，以随机本机凭据保护；网关只对本机开放。
- Key、运行数据、客户端备份保存在应用数据目录，均不进入仓库和发行资源。备份包含原配置，作为本机资料保存。
- 配置预览带哈希检查，原文件在预览后变化会中止写入；恢复前也核对当前文件和全部备份。
- 默认尽量沿用上次网关端口。端口被占用时显示重新接入提示，避免把旧配置视为真实连接成功。
- 运行时遵循现有网络环境，应用不修改 VPN 或系统代理设置。
